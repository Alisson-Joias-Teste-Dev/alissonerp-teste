## Story

**As a** auditor do sistema (interno ou externo),
**I want** que toda mutação em entidades críticas seja registrada em `alissonerp.audit_log` com dados antes/depois, autor, IP, user-agent,
**so that** seja possível reconstruir o histórico de qualquer registro e identificar autoria de mudanças sensíveis.

## Acceptance Criteria

1. **AC1:** `alissonerp.audit_log` tem schema completo: `id BIGSERIAL`, `tabela TEXT`, `acao TEXT (INSERT|UPDATE|DELETE)`, `registro_id BIGINT`, `user_id BIGINT`, `dados_antes JSONB`, `dados_depois JSONB`, `criado_em TIMESTAMPTZ`, `ip TEXT`, `user_agent TEXT`. Index em `(tabela, registro_id, criado_em)`.
2. **AC2:** Helper `logAudit(tx, ...)` (Story 1.4) é usado em **100% das rotas POST/PUT/DELETE em alissonerp**.
3. **AC3:** Endpoint `/api/admin/audit-log` (GET) com filtros: tabela, registro_id, user_id, intervalo de data. Retorna paginado.
4. **AC4:** Tela admin `/admin/audit-log` exibe consultas com diff visual entre `dados_antes` e `dados_depois`.
5. **AC5:** Cron diário arquiva registros > 90 dias em `alissonerp.audit_log_archive` (mesma estrutura, particionada por mês).
6. **AC6:** Teste integration valida que toda rota POST/PUT/DELETE migrada gera entrada em `audit_log`.
7. **AC7:** Performance: insert do audit_log < 5ms (medido); não impacta latência de rota crítica.
8. **AC8:** `npx tsc --noEmit` passa.

## Architect Notes (v1.1)

**Migration reservada:** 199 (audit_log schema completo + archive)

**Ajuste crítico §2.2 da validação técnica — granularidade alto-nível:**

❌ **NÃO fazer** (gargalo): logAudit por cada INSERT individual em rotas multi-tabela
```typescript
// Ruim: api/vendas POST gera 8+ INSERTs, 8+ audit logs
INSERT INTO vendas_erp ...; await logAudit(tx, ...);
INSERT INTO itens_venda_erp ...; await logAudit(tx, ...);
// ... 6 mais
```

✅ **Fazer** (granularidade adequada): 1 log de evento de alto nível
```typescript
INSERT INTO vendas_erp ...;
INSERT INTO itens_venda_erp ...;
// ... outros INSERTs
await logAudit(tx, {
  tabela: 'vendas_erp',
  acao: 'venda_criada',
  registro_id: vendaId,
  user_id: user.id,
  dados_depois: { /* resumo, não cada row */ }
});
```

**Performance test obrigatório:** antes da adoção universal, medir latência de rotas críticas (vendas, pcp/apontamentos) com e sem audit. Critério: aumento ≤ 30ms no tempo total.

**Particionamento da `audit_log`:**
```sql
CREATE TABLE audit_log (
  id BIGSERIAL,
  criado_em TIMESTAMPTZ NOT NULL,
  -- outros campos
  PRIMARY KEY (id, criado_em)
) PARTITION BY RANGE (criado_em);

CREATE TABLE audit_log_2026_05 PARTITION OF audit_log
  FOR VALUES FROM ('2026-05-01') TO ('2026-06-01');
-- Cron mensal cria nova partição
```

**Storage uploads (ponto cego 3.3):** uploads de fotos críticas (transferência metal, foto peça serviço) também devem gerar audit log. Adicionar Task: `logAudit` em rotas que chamam `supabase.storage.upload()`.
