## Dev Notes

- **Template runbook** sugerido:
  ```markdown
  # Runbook — {cenário}

  ## Sintoma
  Como o problema se manifesta.

  ## Diagnóstico
  Queries SQL ou comandos para confirmar o problema.

  ## Procedimento
  1. Passo 1
  2. Passo 2

  ## Rollback
  O que fazer se procedimento falhar.

  ## Escalonamento
  Quem acionar se não conseguir resolver.
  ```

## Architect Notes (v1.1)

**Cada runbook DEVE ter exemplo concreto executável:**

- `runbook-rollback-migration.md`: usar exemplo real de migration recente (ex: 192_parametros_sistema)
- `runbook-restaurar-backup.md`: comandos `pg_restore` exatos com paths Windows + WSL
- `runbook-pcp-totais-divergentes.md`: queries de diagnóstico (ex: `SELECT distribuicao_id, total_metal, (SELECT SUM(pmc) FROM ...) FROM pcp WHERE ...`)
- `runbook-fila-sync-falha.md`: como ler `fila_sync_externo` e reprocessar manualmente
- `runbook-drift-directus.md`: como interpretar `mv_drift_directus` e tomar ação
- `runbook-deploy-homolog.md`: passo-a-passo com checklist (tsc, push, wait CI, smoke)
- `runbook-rotacao-secrets.md`: rotação de DATABASE_URL, SUPABASE_KEY, MP token (conforme calendário)
- `runbook-onboarding-dev.md`: clone, .env, npm install, npm run dev, login com user dev

**Validação cruzada:** Jonathan executa pelo menos 3 runbooks **literalmente** seguindo passo-a-passo. Se confundir em algum step, runbook precisa edit.
