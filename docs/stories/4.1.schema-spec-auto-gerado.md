## Story

**As a** desenvolvedor novo no projeto (ou Jonathan precisando consultar estrutura),
**I want** documentação do schema do banco gerada automaticamente a partir de `information_schema`,
**so that** a documentação nunca fique desatualizada e o banco continue sendo a fonte da verdade.

## Acceptance Criteria

1. **AC1:** Script `scripts/generate-schema-doc.ts` extrai do `information_schema`:
   - Tabelas: nome, owner, comentário
   - Colunas: nome, tipo, NOT NULL, default, comentário
   - PK, FKs (cross-schema), índices
   - Views: nome, definição SQL
   - Triggers: nome, tabela, função, evento, condição
   - Funções: nome, parâmetros, retorno, body (truncado se > 1000 linhas)
2. **AC2:** Output em formato markdown estruturado em:
   - `docs/schema/alissonerp.md`
   - `docs/schema/public.md` (READONLY)
   - `docs/schema/directus.md` (READONLY)
3. **AC3:** Cada tabela tem seção: descrição, colunas, FKs, triggers ativos, views relacionadas.
4. **AC4:** Workflow CI `.github/workflows/schema-sync.yml` roda script a cada push em homolog e gera PR automático se docs/schema/ mudou.
5. **AC5:** Falha CI se schema mudou e doc não foi commitado (gate manual ou auto-PR).
6. **AC6:** Script roda em < 30s contra produção.
7. **AC7:** README em `docs/schema/README.md` explica como ler e como atualizar.
8. **AC8:** `npx tsc --noEmit` passa.

## Architect Notes (v1.1)

**Queries-base do extractor:**

```sql
-- Tabelas
SELECT table_schema, table_name, obj_description((table_schema||'.'||table_name)::regclass) AS comment
FROM information_schema.tables
WHERE table_schema IN ('alissonerp', 'public', 'directus')
  AND table_type = 'BASE TABLE';

-- Colunas
SELECT table_schema, table_name, column_name, data_type, is_nullable, column_default,
       col_description((table_schema||'.'||table_name)::regclass, ordinal_position) AS comment
FROM information_schema.columns
WHERE table_schema IN ('alissonerp', 'public', 'directus')
ORDER BY table_schema, table_name, ordinal_position;

-- FKs
SELECT tc.table_schema, tc.table_name, kcu.column_name,
       ccu.table_schema AS referenced_schema, ccu.table_name AS referenced_table, ccu.column_name AS referenced_column
FROM information_schema.table_constraints tc
JOIN information_schema.key_column_usage kcu USING (constraint_name, table_schema)
JOIN information_schema.constraint_column_usage ccu USING (constraint_name, table_schema)
WHERE tc.constraint_type = 'FOREIGN KEY';

-- Triggers
SELECT trigger_schema, trigger_name, event_object_table, event_manipulation, action_timing, action_statement
FROM information_schema.triggers
WHERE trigger_schema IN ('alissonerp', 'public', 'directus');

-- Funções
SELECT routine_schema, routine_name, data_type AS return_type, routine_definition
FROM information_schema.routines
WHERE routine_schema IN ('alissonerp', 'public', 'directus')
  AND routine_type = 'FUNCTION';
```

**Output dividido por área** (310 tabelas em 3 arquivos é muito):
- `docs/schema/alissonerp-vendas.md` (vendas, ordens, contas_receber, etc.)
- `docs/schema/alissonerp-pcp.md` (pcp, distribuicoes, apontamentos, etc.)
- `docs/schema/alissonerp-estoque.md` (movimentacoes, insumos, depositos, etc.)
- `docs/schema/alissonerp-comercial.md` (vendas_erp, vale_troca, crediario, etc.)
- `docs/schema/alissonerp-admin.md` (usuarios, roles, audit_log, etc.)
- `docs/schema/public.md` (READONLY)
- `docs/schema/directus.md` (READONLY)
