## Story

**As a** desenvolvedor escrevendo testes integration contra o banco de produção,
**I want** infra que garanta que testes nunca persistam dados reais (mitigações M1, M2, M3, M6 do plano §3.4),
**so that** posso atingir cobertura sem comprometer integridade de produção até o banco de teste real existir (Story 4.7).

## Acceptance Criteria

1. **AC1:** `src/test/db.ts` exporta helper `withTestTx<T>(fn)` que executa `fn` dentro de `sql.begin()` e **força ROLLBACK sempre** ao final, mesmo em sucesso.
2. **AC2:** ESLint custom rule (`scripts/eslint-rules/no-direct-sql-in-tests.js`) bloqueia uso de `sql\`...\`` ou `db.query` em arquivos `src/__tests__/integration/**` fora de `withTestTx`. Lint falha CI.
3. **AC3:** Migration cria schema `alissonerp_test` com cópia estrutural de tabelas: `usuarios`, `produtos`, `contatos_fiscais`, `vendedores`, `clientes`, `depositos`, `insumos`, `categorias_insumo`. Sem dados de produção.
4. **AC4:** Seed inicial em `alissonerp_test`: 1 usuário por role (10 roles), 5 produtos, 3 fornecedores, 2 vendedores, 1 deposito, 1 cliente "fictício".
5. **AC5:** Usuário Supabase `ci_test_user` criado com role `desenvolvedor` (acesso total). Auth.users + alissonerp.usuarios.
6. **AC6:** Helper `criarRegistroMarcado(tx, tabela, dados)` injeta `criado_por: 'CI_TEST_USER'` (ou marker equivalente) automaticamente.
7. **AC7:** Migration cria função `alissonerp.fn_limpar_fixtures_teste()` que deleta registros marcados em todas as tabelas relevantes onde `criado_por = 'CI_TEST_USER' AND criado_em < NOW() - INTERVAL '1 day'`.
8. **AC8:** Cron diário às 3h chama `fn_limpar_fixtures_teste()`. Endpoint `/api/admin/test-fixtures` (GET) mostra contagem por tabela e botão "Limpar agora" (POST).
9. **AC9:** Documentação `docs/runbooks/runbook-testes-em-producao.md` (DEVE ser lido antes de escrever qualquer test integration).

## Architect Notes (v1.1)

**Migrations reservadas:** 195 (schema test) + 196 (cleanup function)

**Ajuste crítico §2.1 — `withTestTx` com search_path:**
```typescript
class RollbackTestSignal extends Error {}

export async function withTestTx<T>(
  fn: (tx: postgres.Sql) => Promise<T>,
  opts?: { schema?: 'alissonerp' | 'alissonerp_test' }
): Promise<T> {
  let result: T;
  try {
    await sql.begin(async (tx) => {
      if (opts?.schema === 'alissonerp_test') {
        await tx`SET LOCAL search_path = alissonerp_test, public`;
      }
      result = await fn(tx);
      throw new RollbackTestSignal();
    });
  } catch (e) {
    if (!(e instanceof RollbackTestSignal)) throw e;
  }
  return result!;
}
```

**Por que `SET LOCAL` e não `SET`:** revertido automaticamente com ROLLBACK. Garantia que search_path não vaza para outras conexões do pool.

**Schema `alissonerp_test` — replicação estrutural sem FK cross-schema:**
```sql
CREATE SCHEMA IF NOT EXISTS alissonerp_test;
CREATE TABLE alissonerp_test.usuarios AS TABLE alissonerp.usuarios WITH NO DATA;
ALTER TABLE alissonerp_test.usuarios ADD PRIMARY KEY (id);
-- FKs cross-schema removidas, todas internas a alissonerp_test
```

**Risco crítico:** test que esquece `withTestTx` vaza INSERT para produção. **Lint rule é mandatória** e DEVE bloquear CI.
