## Story

**As a** desenvolvedor escrevendo APIs,
**I want** um wrapper `defineRoute()` que centraliza validação Zod, autenticação, permissões e audit log,
**so that** todas as rotas sigam o mesmo contrato seguro e dados ruins nunca cheguem ao banco.

## Acceptance Criteria

1. **AC1:** `src/lib/api-handler.ts` exporta `defineRoute({ method, inputSchema?, outputSchema?, requireRole?, requirePermissao?, handler })` que retorna um Next.js `Route` handler.
2. **AC2:** Wrapper valida input com `inputSchema.parse(await req.json())` e retorna 400 com mensagem clara se falhar.
3. **AC3:** Wrapper valida output com `outputSchema.parse(...)` antes de retornar; falha = 500 com log de erro estruturado.
4. **AC4:** `src/lib/auth-server.ts` exporta `requireAuth(req)` que retorna `{ id, email, role }` ou lança `AuthError(401)`.
5. **AC5:** `src/lib/auth-server.ts` exporta `requirePermissao(user, permissao)` que valida via `temPermissao()` e lança `ForbiddenError(403)`.
6. **AC6:** `src/lib/audit.ts` exporta `logAudit(tx, { tabela, acao, registro_id, user_id, dados_antes?, dados_depois? })` que insere em `alissonerp.audit_log` dentro da transação fornecida.
7. **AC7:** 5 rotas piloto migradas para o wrapper: `api/compras` POST, `api/vendas` POST, `api/crediario/[id]/registrar-pagamento` POST, `api/contatos` POST, `api/pcp/apontamentos` POST. Cada uma define schemas Zod e usa o wrapper.
8. **AC8:** TypeScript infere tipos do schema sem casting manual. `npx tsc --noEmit` passa em todas as 5 rotas piloto.

## Architect Notes (v1.1)

**Estimate revisado:** 3d → **4d** (+1d para implementar RLS interaction)

**Adições obrigatórias da validação técnica:**

1. **`defineRoute` aceita `bypassRls?: boolean`** (default `false`)
2. **Conexão como usuário real:** novo helper `src/lib/db-rls.ts`:
   ```typescript
   export async function sqlAsUser(userId: number, role: string, fn: (tx: Sql) => Promise<T>) {
     return sql.begin(async (tx) => {
       await tx`SET LOCAL "request.jwt.claims" = ${JSON.stringify({ sub: userId, role })}`;
       return fn(tx);
     });
   }
   ```
3. **`outputSchema` lida com NUMERIC:** Zod schemas devem usar `z.coerce.number()` para campos NUMERIC do PostgreSQL (postgres v3 retorna como string).
4. **Rate limiting opcional:** `defineRoute({ rateLimit: { max, windowMs } })` para endpoints admin (ponto cego 3.6).

**Template de rota completo (atualizado v1.1):**
```typescript
export const POST = defineRoute({
  inputSchema: InputSchema,
  outputSchema: OutputSchema,
  requirePermissao: "compras.criar",
  rateLimit: { max: 10, windowMs: 60_000 },
  bypassRls: false,    // RLS atua
  handler: async (req, { user, body, tx }) => {
    // tx já é sqlAsUser(user.id, user.role)
    // ...
  },
});
```

**ADRs aplicáveis:**
- 0001 (a criar) — Zod validation wrapper
- **0012** (criada v1.1) — RLS vs Application Auth

**Risco:** se RLS bloquear silenciosamente (postgres retorna 0 rows), wrapper deve detectar e lançar erro claro. Adicionar AC: "operação que esperava modificar 1 row mas modificou 0 deve lançar erro `RowNotAffectedError`".
