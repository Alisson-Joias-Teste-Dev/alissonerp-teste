## Story

**As a** owner do ERP integrado com Tiny e potencialmente outros sistemas,
**I want** que falhas temporárias sejam reprocessadas com retry exponencial e falhas permanentes gerem alerta,
**so that** integrações externas sejam resilientes sem comprometer dados do banco.

## Acceptance Criteria

1. **AC1:** Worker `scripts/processar-fila-sync.ts` (criado em Story 1.2) é expandido com retry exponencial: tentativas em 1m, 5m, 15m, 1h, 6h.
2. **AC2:** Após 5 tentativas, item é marcado como `falha_definitiva` e gera notificação (mesma stack de Story 1.5/1.6).
3. **AC3:** Worker é resiliente a múltiplas instâncias (lock pessimista em row sendo processado).
4. **AC4:** Endpoint `/api/admin/fila-sync` (Story 1.2) é expandido com:
   - GET: lista paginada com filtros, contadores agregados
   - POST `/admin/fila-sync/[id]/reprocessar`: força reprocessamento de item em `falha_definitiva`
   - POST `/admin/fila-sync/limpar`: marca todos antigos > 30 dias como arquivados
5. **AC5:** Tela admin `/admin/fila-sync` mostra status real-time + botões de ação.
6. **AC6:** Métricas exportadas (logs estruturados): items processados/min, taxa de falha, tempo médio em fila.
7. **AC7:** Cron `pg_cron` ou agendador externo dispara worker a cada 1min.
8. **AC8:** Teste integration: força falha temporária no Tiny → item permanece na fila com `tentativas` incrementando até sucesso.

## Dev Notes

- **PostgreSQL `FOR UPDATE SKIP LOCKED`** é a forma idiomática de fila distribuída em SQL.
- **Idempotência:** payload do Tiny pode ser aplicado 2x (em caso de falha entre sucesso real e marcar processado). Tiny deve aceitar payload duplicado (chave de idempotência). Documentar.
- **Falha definitiva ≠ erro de código.** Se o payload for malformado por bug, item entra em retry infinito. Considerar threshold de error type.

## Architect Notes (v1.1)

**Migration reservada:** 200 (colunas extras `proxima_execucao` + idempotency_key)

**Lógica de retry exponencial:**
```typescript
function calcularProximaExecucao(tentativas: number): Date {
  const delays = [60, 300, 900, 3600, 21600]; // 1m, 5m, 15m, 1h, 6h
  const delay = delays[Math.min(tentativas, delays.length - 1)];
  return new Date(Date.now() + delay * 1000);
}
```

**Lock distribuído com `FOR UPDATE SKIP LOCKED`:**
```sql
-- Worker pega 10 itens sem competir
SELECT * FROM alissonerp.fila_sync_externo
WHERE status = 'pendente'
  AND (proxima_execucao IS NULL OR proxima_execucao <= NOW())
ORDER BY criado_em
LIMIT 10
FOR UPDATE SKIP LOCKED;
```

**Idempotência com Tiny:** se item processou e crashou antes de marcar `processado`, próxima tentativa pode duplicar. Solução: incluir `idempotency_key` no payload Tiny (Tiny aceita).

**Alerta após 5 tentativas:**
- Insert em `notificacoes` com user_id=admin
- Webhook (mesmo de Story 1.5)
- Email opcional via Resend ou Supabase Edge Function
