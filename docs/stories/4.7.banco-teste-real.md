## Story

**As a** owner que aceitou o risco temporário de testes em produção (decisão de 2026-04-29),
**I want** um banco de teste real provisionado em até 30 dias úteis,
**so that** o débito técnico §3.4 do plano seja saldado e testes nunca mais toquem produção.

## Acceptance Criteria

1. **AC1:** Decisão tomada e documentada em `docs/adr/0011-banco-de-teste.md`:
   - Opção A: Docker Postgres efêmero local + dump de schema
   - Opção B: Supabase de teste novo (free tier ou paid)
2. **AC2:** Banco provisionado, acessível via `DATABASE_URL_TEST` em secrets do CI.
3. **AC3:** Schema sincronizado com produção via `scripts/sync-schema-to-test.sh` que copia DDL (sem dados sensíveis) semanalmente.
4. **AC4:** Seed inicial replicando `alissonerp_test` (Story 2.1) + dados sintéticos para tests E2E.
5. **AC5:** Todos os testes integration migrados para usar `DATABASE_URL_TEST`. Confirmação via auditoria de `pg_stat_activity` em produção: zero acesso de `ci_test_user`.
6. **AC6:** `ci-integration.yml` atualizado: **remover** restrição de janela noturna (M4 não mais necessária).
7. **AC7:** Schema `alissonerp_test` em produção pode ser deprecado após 30 dias (manter por rede de proteção).
8. **AC8:** `npx tsc --noEmit` + suite completa passa contra novo banco.

## Architect Notes (v1.1)

**Comparativo Opção A vs B:**

| Critério | Opção A: Docker local | Opção B: Supabase paid |
|----------|----------------------|----------------------|
| Custo | $0 | ~$25/mês |
| Setup time | 1d | 0.5d |
| Fidelidade ao prod | Média (sem RLS Supabase real) | Alta (mesma stack) |
| Acesso | Local | Internet |
| Limpeza | Container destruído a cada run | Cron necessário |
| CI integration | Spin-up no job | Conexão direta |

**Recomendação Architect: Opção B (Supabase paid).**
- Fidelidade alta importa (RLS, auth, storage idênticos)
- $25/mês é negligível vs custo de bug em prod
- Setup mais rápido — desbloqueia mais cedo

**Plano de migração (3 dias):**

Dia 1:
- Provisionar Supabase project novo
- Configurar `DATABASE_URL_TEST` em secrets
- Script `sync-schema-to-test.sh` que copia DDL semanalmente

Dia 2:
- Atualizar `vitest.config.ts` para usar `DATABASE_URL_TEST`
- Rodar suite completa — confirmar que passa
- Auditoria `pg_stat_activity` em produção: 0 acessos do `ci_test_user`

Dia 3:
- Atualizar `ci-integration.yml`: remover restrição janela noturna
- Manter schema `alissonerp_test` em produção por mais 30 dias (rede de proteção)
- Documentar deprecation em `docs/runbooks/`
