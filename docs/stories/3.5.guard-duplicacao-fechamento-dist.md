## Story

**As a** ourives e gerente de fábrica que dependem dos totais de PCP corretos,
**I want** que `fn_processar_fechamento_dist` impeça acúmulo duplicado quando uma distribuição é fechada mais de uma vez,
**so that** totais (`total_metal`, `total_pedras_un`, `total_pedras_g`) reflitam a realidade física e não somem 2x por erro manual.

## Acceptance Criteria

1. **AC1:** Migration cria índice único parcial: `CREATE UNIQUE INDEX idx_unico_fechamento_dist ON alissonerp.fechamentos_distribuicao (distribuicao_id) WHERE status = 'concluido'`.
2. **AC2:** Função `fn_processar_fechamento_dist` modificada para verificar se já existe fechamento `status='concluido'` para a mesma `distribuicao_id` ANTES de acumular em `pcp.total_*`.
3. **AC3:** Se duplicação detectada, função lança `RAISE EXCEPTION 'distribuicao_ja_fechada' USING ERRCODE = 'P0001'`.
4. **AC4:** Frontend trata erro `P0001 distribuicao_ja_fechada` com mensagem amigável: "Esta distribuição já foi fechada anteriormente."
5. **AC5:** Teste integration: tenta fechar mesma distribuição 2x → segundo retorna erro, totais PCP não duplicaram.
6. **AC6:** Teste manual em homolog: cenário real reproduzido (Jonathan executa fluxo).
7. **AC7:** Migration é **aditiva** (índice + ALTER FUNCTION com CREATE OR REPLACE). Sem DROP. Sem perda de dados existentes.
8. **AC8:** Documentação em `docs/adr/0008-guard-duplicacao-fechamento.md`.

**Guard na função:**
```sql
CREATE OR REPLACE FUNCTION alissonerp.fn_processar_fechamento_dist()
RETURNS TRIGGER AS $$
BEGIN
  -- Guard novo
  IF EXISTS (
    SELECT 1 FROM alissonerp.fechamentos_distribuicao
    WHERE distribuicao_id = NEW.distribuicao_id
      AND status = 'concluido'
      AND id != NEW.id
  ) THEN
    RAISE EXCEPTION 'distribuicao_ja_fechada' USING ERRCODE = 'P0001';
  END IF;

  -- ... resto da lógica original (acumular em pcp.total_*)
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
```
