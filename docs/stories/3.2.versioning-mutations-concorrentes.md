## Story

**As a** usuário trabalhando em equipe (vendedoras editando mesma venda, gerentes alterando ordens em paralelo),
**I want** que o sistema detecte e impeça que minhas alterações sobrescrevam acidentalmente as de outro usuário,
**so that** o problema #9 do diagnóstico (last-write-wins) seja eliminado nas top 4 entidades críticas.

## Acceptance Criteria

1. **AC1:** Migration garante que `updated_at TIMESTAMPTZ` existe em: `vendas_erp`, `ordens`, `protocolos`, `contas_receber` (já existe na maioria; story confirma).
2. **AC2:** Trigger `trg_atualizar_updated_at` em cada uma dessas 4 tabelas atualiza `updated_at = NOW()` em todo UPDATE.
3. **AC3:** `defineRoute` (Story 1.4) aceita opção `versionField: 'updated_at'`. Quando configurado em PUT/PATCH, valida `body.updated_at` contra valor atual no banco.
4. **AC4:** Servidor retorna **HTTP 409 Conflict** quando `updated_at` divergente, com payload `{ error: 'version_conflict', current: { updated_at: ..., dados_atuais: ... } }`.
5. **AC5:** Frontend (vendas, ordens, protocolos, crediário) trata 409: mostra modal "Outro usuário alterou. Recarregar?" com diff dos campos divergentes.
6. **AC6:** Teste integration: dispara 2 PUTs simultâneos com mesmo `updated_at` → primeiro vence, segundo recebe 409.
7. **AC7:** Documentação em `docs/adr/0006-versioning-mutations.md` explicando padrão e quando aplicar.
8. **AC8:** `npx tsc --noEmit` passa.

## Dev Notes

- **Padrão clássico** de optimistic concurrency control.
- **Por que 4 entidades:** vendas, ordens, protocolos, crediário são as únicas com edição concorrente real. Outras têm flow mais sequencial.
- **Cuidado Directus:** ordens vêm do PDV (Directus). PDV não envia `updated_at` no formato do alissonerp. Versioning aplica apenas a edições em alissonerp; sync Directus continua sem versioning.

### Testing

## Architect Notes (v1.1)

**Trigger de auto-update genérico:**
```sql
CREATE OR REPLACE FUNCTION alissonerp.fn_atualizar_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_vendas_erp_updated_at
BEFORE UPDATE ON alissonerp.vendas_erp
FOR EACH ROW EXECUTE FUNCTION alissonerp.fn_atualizar_updated_at();
-- Repetir para ordens, protocolos, contas_receber
```

**Wrapper Zod expandido (Story 1.4):**
```typescript
defineRoute({
  method: 'PUT',
  inputSchema: z.object({ /* ... */ updated_at: z.string().datetime() }),
  versionField: 'updated_at',
  handler: async (req, { body, tx }) => {
    // wrapper já validou updated_at vs banco antes do handler rodar
  }
});
```

**Frontend pattern (React Query):**
```typescript
function useEditarVenda() {
  const qc = useQueryClient();
  return useMutation({
    mutationFn: (input) => apiFetch(`/api/vendas/${input.id}`, {
      method: 'PUT',
      body: JSON.stringify(input), // inclui updated_at
    }),
    onError: (error) => {
      if (error.status === 409) {
        showVersionConflictModal({
          onReload: () => qc.invalidateQueries(['venda', input.id]),
        });
      }
    }
  });
}
```
