## Story

**As a** equipe garantindo qualidade end-to-end,
**I want** 12 fluxos E2E cobrindo os caminhos críticos do sistema, respeitando mitigação **M5** (read-only em produção ou usando marcador `CI_TEST_USER`),
**so that** regressões em UI sejam pegas antes de chegar ao usuário final.

## Acceptance Criteria

1. **AC1:** 6 testes E2E **read-only** implementados (validam UI contra dados reais sem mutar):
   - Login + ver permissões (5 roles distintas)
   - Dashboard fábrica: KPIs aparecem e somam corretamente
   - Cofre ouro: saldo é exibido
   - Lista de vendas: filtros + paginação
   - Lista de PCP: ordens em cada etapa
   - Estoque comercial: saldos consolidados
2. **AC2:** 6 testes E2E **com mutation marcada** (usam `CI_TEST_USER` ou conta de teste isolada):
   - Criar venda completa em conta de teste (cliente=-1, vendedor=-1)
   - Aprovar desconto em venda de teste (consultora-test → admin-test)
   - Criar ordem PCP + apontamento em produto de teste
   - Concluir protocolo de teste (ida)
   - Crediário: registrar pagamento parcial em conta de teste
   - Estoque: transferir entre locais usando produto de teste
3. **AC3:** Cada teste de mutation valida no banco que registro tem marcador `criado_por='CI_TEST_USER'` antes de finalizar.
4. **AC4:** Job M6 (cron de limpeza) confirma 0 órfãos no dia seguinte de cada execução.
5. **AC5:** Suite completa < 10min em CI noturno.
6. **AC6:** Screenshots e videos uploaded em falhas.
7. **AC7:** Cada teste tem documentação inline explicando o fluxo.
8. **AC8:** `npm run test:e2e` passa localmente apontando para homolog.

## Architect Notes (v1.1)

**Sub-task escondida (estimate +1d):** ~50 componentes precisam de `data-testid` em elementos clicáveis críticos. Sem isso, seletores Playwright ficam frágeis (text content / class).

**Convenção `data-testid`:**
- Botões: `btn-{acao}-{contexto}` (ex: `btn-aprovar-desconto`, `btn-criar-venda`)
- Inputs: `input-{campo}` (ex: `input-cliente-busca`, `input-preco-unitario`)
- Cards/items: `card-{tipo}-{id}` (ex: `card-venda-123`)
- Modais: `modal-{acao}` (ex: `modal-confirmar-cancelamento`)

**Componentes que precisam testid (lista parcial):**
- `NovaVendaClient.tsx` — campos cliente, vendedor, produtos, descontos, parcelas
- `CrediarioClient.tsx` — botões de baixa, MP, filtros
- `ProtocoloClient.tsx` — botões concluir, criar, filtros
- ~12 modais reusáveis

**Smoke test M5:** primeiro Playwright deve confirmar que **nenhum** test consegue executar `DELETE` ou `UPDATE` que afete row sem `criado_por='CI_TEST_USER'`. Se conseguir, lint rule estranha — investigar.
