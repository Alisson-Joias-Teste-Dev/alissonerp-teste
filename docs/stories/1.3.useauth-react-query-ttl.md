## Story

**As a** administrador do ERP,
**I want** que mudanças de role e permissões dos usuários reflitam no frontend em até 5 minutos sem precisar de logout,
**so that** o banco volte a ser fonte da verdade para autorização e elevações/restrições de acesso sejam efetivas em tempo razoável.

## Acceptance Criteria

1. **AC1:** `<QueryClientProvider>` adicionado no root layout (`src/app/layout.tsx`) com configuração padrão (`staleTime: 30s`, `retry: 1`).
2. **AC2:** `src/hooks/useAuth.ts` reescrito usando `useQuery({ queryKey: ['auth','me'], staleTime: 5*60_000 })` que busca em paralelo `/api/user/role` e `/api/user/permissoes`.
3. **AC3:** Cache module-scoped antigo (`cachedState`, `inflightPromise`) é removido — React Query gerencia.
4. **AC4:** `supabase.auth.onAuthStateChange` invalida a query (`queryClient.invalidateQueries({ queryKey: ['auth'] })`) quando usuário muda.
5. **AC5:** Função `invalidarCacheAuth()` exportada do hook para forçar revalidação após mutações administrativas.
6. **AC6:** Endpoint admin `/api/admin/usuarios/[id]/forcar-revalidacao` (POST) que insere notificação de invalidação (rascunho — implementação completa via WebSocket fica fora do escopo desta story; por enquanto apenas o admin tem botão "Forçar logout do usuário X" que chama Supabase admin API).
7. **AC7:** Teste E2E (Playwright — preparação para Story 2.6): admin troca role de uma consultora teste no banco → consultora recarrega → vê novo acesso. Validação manual em homolog suficiente para esta story.
8. **AC8:** Componentes que usam `useAuth` continuam funcionando sem regressão. Verificar pelo menos: `MainLayout`, `Sidebar`, `ProtocoloClient`, `VendasClient`, `CrediarioClient`, qualquer page que use `if (auth.role === ...)`.

## Architect Notes (v1.1)

**Estimate revisado:** 2d → **3d** (17+ componentes consumindo `useAuth` exigem smoke individual)

**Componentes afetados** (via grep `useAuth`):
- `MainLayout`, `Sidebar`, `Header` (layout)
- `VendasClient`, `NovaVendaClient`, `CrediarioClient`, `ProtocoloClient` (telas críticas)
- ~12 outros componentes de listas/dashboards

**Pegadinha React 19 + Next 16:**
- `useAuth` em Server Components não funciona — manter como Client-only (`"use client"` no consumidor)
- `QueryClientProvider` deve estar em layout client component (criar `src/components/providers.tsx`)

**Configuração React Query recomendada:**
```typescript
new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 30_000,        // 30s default
      gcTime: 5 * 60_000,       // 5min cache time
      refetchOnWindowFocus: true,
      retry: 1,
    },
  },
});
```

Para `useAuth` especificamente: `staleTime: 5 * 60_000` (5min — sensível a mudanças de role).

**ADR aplicável:** 0003-react-query-cache-strategy (será criado em Story 4.3).

**Risco:** se `<QueryClientProvider>` for adicionado em layout *server* component, falha no build. Mover providers para client component dedicado.
