## Story

**As a** auditor financeiro do sistema (e desenvolvedor mantenedor),
**I want** que toda dupla-entrada de movimentação de ouro siga o **mesmo padrão** (manual com 2 INSERTs auditáveis, não via function que esconde IDs),
**so that** rastrear movimentações seja consistente e o problema #10 do diagnóstico seja resolvido.

## Acceptance Criteria

1. **AC1:** ADR `docs/adr/0002-dupla-entrada-pattern.md` decide e documenta padrão único: **manual com 2 INSERTs**, ambos com mesmo `transferencia_id` (ou marcador equivalente para correlação).
2. **AC2:** Função `fn_criar_par_movimentacao` é refatorada para retornar `(saida_id BIGINT, entrada_id BIGINT)` (atualmente retorna `void`).
3. **AC3:** Rotas que usam `fn_criar_par_movimentacao` são migradas para padrão manual com 2 INSERTs OU continuam usando a função mas capturando os IDs retornados:
   - `src/app/api/service/carregar-aditivo/route.ts:77`
   - `src/app/api/service/carregar-solda/route.ts:77`
4. **AC4:** Documentação em CLAUDE.md §3 atualizada explicando padrão.
5. **AC5:** Teste integration valida que após dupla-entrada existe row de saída + row de entrada com mesmo `transferencia_id` em `movimentacoes_estoque`.
6. **AC6:** Lint check (custom rule ou regex grep) que detecta uso de padrão antigo (`fn_criar_par_movimentacao` sem capturar IDs) e flag em CI.
7. **AC7:** `npx tsc --noEmit` passa.
8. **AC8:** ADR aprovado por @architect antes de implementação.

## Architect Notes (v1.1)

**Migration reservada:** 198

**Decisão arquitetônica recomendada:** **padrão manual** (2 INSERTs explícitos) em vez de function. Razões:
1. **Auditável:** cada INSERT tem ID separado em `movimentacoes_estoque`, traceable
2. **Flexível:** pode ajustar `marcador`, `obs`, `local_estoque_id` por caso
3. **Sem black box:** dev novo entende o que está acontecendo lendo o código

Function `fn_criar_par_movimentacao` é mantida (refatorada para retornar IDs), mas seu uso é **desencorajado** para casos novos.

**Padrão alvo:**
```typescript
await tx.begin(async (tx) => {
  // Saída
  const [saida] = await tx`
    INSERT INTO alissonerp.movimentacoes_estoque
      (insumo_id, saida, deposito_id, local_estoque_id, marcador, transferencia_id, obs)
    VALUES (${insumoId}, ${peso}, ${depositoOrigemId}, ${localOrigemId}, 'TR', ${transferId}, ${obs})
    RETURNING id
  `;

  // Entrada (mesmo transferencia_id correlaciona o par)
  const [entrada] = await tx`
    INSERT INTO alissonerp.movimentacoes_estoque
      (insumo_id, entrada, deposito_id, local_estoque_id, marcador, transferencia_id, obs)
    VALUES (${insumoId}, ${peso}, ${depositoDestinoId}, ${localDestinoId}, 'TR', ${transferId}, ${obs})
    RETURNING id
  `;
});
```

**ADR aplicável:** 0002 — Dupla-Entrada Pattern (criar nesta story).
