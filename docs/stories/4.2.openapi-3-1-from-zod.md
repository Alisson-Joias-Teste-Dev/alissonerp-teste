## Story

**As a** desenvolvedor (interno) e potencial integrador (externo),
**I want** especificação OpenAPI 3.1 gerada automaticamente dos schemas Zod usados nas rotas,
**so that** a documentação da API esteja sempre alinhada com o código real (single source of truth) e seja navegável via Swagger UI.

## Acceptance Criteria

1. **AC1:** `zod-to-openapi` instalado e configurado em `src/lib/openapi-registry.ts`.
2. **AC2:** `defineRoute` (Story 1.4) registra automaticamente o schema no `OpenAPIRegistry` global.
3. **AC3:** Endpoint `/api/openapi.json` serve spec OpenAPI 3.1 atualizada em runtime.
4. **AC4:** Página `/docs/api` (apenas em dev/homolog ou para roles admin) renderiza Swagger UI navegável.
5. **AC5:** Script `scripts/generate-openapi.ts` gera `docs/api/openapi.json` versionado em git.
6. **AC6:** OpenAPI spec inclui: paths, métodos, parâmetros, request bodies, responses (200/400/401/403/404/409/500), security schemes (Bearer/Cookie).
7. **AC7:** 100% das rotas usando `defineRoute` aparecem no spec.
8. **AC8:** Workflow CI valida que spec gerada é válida (`npx @apidevtools/swagger-cli validate`).

## Architect Notes (v1.1)

**Limitações conhecidas de `zod-to-openapi`:**

❌ Não cobre bem:
- `z.discriminatedUnion()` complexos (conversão para `oneOf` falha em casos específicos)
- `z.lazy()` para schemas recursivos
- `.refine()` ou `.transform()` que mudam a forma do dado

✅ Cobre bem:
- Tipos básicos (string, number, boolean, array, object)
- `z.optional()`, `z.nullable()`, `z.default()`
- `z.enum()`
- `z.string().email().min().max()`

**Padrão arquitetônico para evitar problema:**
```typescript
// RUIM: transform muda forma — OpenAPI confunde
const InputSchema = z.object({
  preco: z.string().transform(s => parseFloat(s))
});

// BOM: separar parsing e transform
const InputRawSchema = z.object({ preco: z.string() });
const transformInput = (raw: z.infer<typeof InputRawSchema>) => ({
  ...raw, preco: parseFloat(raw.preco)
});
// Use InputRawSchema no defineRoute → OpenAPI gerado é claro
```

**Validação por amostragem (ajuste 2.7):** após gerar, validar 5 rotas representativas:
```bash
npx @apidevtools/swagger-cli validate docs/api/openapi.json
```

**Cobertura incremental:** rotas migradas para `defineRoute` aparecem no OpenAPI. Esta story garante que sistema funciona; cobertura de 100% das 334 rotas é gradual.
